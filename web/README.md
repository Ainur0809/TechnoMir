# Демо-сайт ТехноМир

Интернет-магазин поверх базы `shop` из Docker. Каждая кнопка на сайте выполняет
настоящие SQL-команды в той же базе, которую вы смотрите в DBeaver. Внизу страницы
есть **журнал SQL**: в нём видно каждую команду, её параметры, число строк, время,
`BEGIN` / `COMMIT` / `ROLLBACK` и текст ошибки PostgreSQL. Кнопка
«Копировать для DBeaver» копирует команду с уже подставленными значениями.

## Запуск

Нужны Java 17+ (подойдёт JDK из IntelliJ) и запущенная база.

```bash
docker compose up -d      # в корне проекта, если база ещё не запущена
./web/run.sh              # компиляция и запуск сайта
```

Открыть http://localhost:8088. Остановить — `Ctrl+C` в терминале.

`run.sh` берёт драйвер PostgreSQL JDBC из `~/.m2`, а если его там нет — один раз
скачивает в `web/lib/`. Внешних библиотек больше нет: сервер написан на встроенном
в Java `HttpServer`.

Сайт опирается на `v_order_summary`, `v_product_stats` и `place_order` из части 7.
Если после `docker compose down -v` вы ещё не выполнили `07_views_procedures.sql`,
сайт при старте создаст их сам тем же текстом, что в файле (и напишет об этом в терминале).

Другие параметры подключения — через переменные окружения:
`DB_URL`, `DB_USER`, `DB_PASS`, `PORT`.

## Что где показывает

| На сайте | Что происходит в базе | Часть |
|---|---|---|
| Дерево категорий слева | рекурсивный CTE `WITH RECURSIVE` | 9 |
| Фильтры, поиск, сортировка | `SELECT` с `JOIN`, `ILIKE` только через параметры `?` | 4, 8 |
| «Без категории» | `category_id IS NULL` — те самые 2 товара | 3, 4 |
| Оформление заказа из корзины | явная транзакция: `BEGIN` → `INSERT orders` → `SELECT … FOR UPDATE` → `INSERT order_items` → `UPDATE products SET stock` → `INSERT payments` → `COMMIT` | 6 |
| Заказ больше остатка | `CHECK (stock >= 0)` отклоняет `UPDATE`, затем `ROLLBACK` — заказа нет | 2, 6 |
| Товары в заказе блокируются по возрастанию id | защита от deadlock | 6.6 |
| Промокод `ТЕХНО1000` | скидка только в `orders.total`, `unit_price` прежний | 1.4, 4.3.20 |
| «Купить в 1 клик» | `SELECT place_order(…)`; для товара без остатка (id 8) — `RAISE EXCEPTION` и откат | 7.2 |
| Отмена заказа | транзакция: остаток возвращается, платёж — `refunded`, статус — `cancelled` | 6 |
| Второй отзыв от того же покупателя | ошибка `UNIQUE (product_id, customer_id)` | 2 |
| Управление → смена статуса | `UPDATE orders`, значения ограничены `CHECK` | 2 |
| Управление → удалить заказ | `ON DELETE CASCADE` уносит позиции и платежи | 1.3, 3.4 |
| Управление → удалить товар с продажами | `ON DELETE RESTRICT` не даёт удалить | 1.3 |
| Управление → цена или остаток меньше нуля | `CHECK (price > 0)`, `CHECK (stock >= 0)` | 2 |
| Управление → строк в таблицах | `UNION ALL` из 3.2, изменения подсвечены | 3.2 |
| Заказы и товары в управлении | `SELECT` из view `v_order_summary` и `v_product_stats` | 7.1 |

## Сценарий показа на защите (2–3 минуты)

1. Открыть сайт и DBeaver рядом. В шапке сайта — те же 60 заказов, что даёт
   `SELECT COUNT(*) FROM orders;`.
2. Положить в корзину два товара, ввести `ТЕХНО1000`, оплатить картой.
   В журнале — вся транзакция до `COMMIT`. В DBeaver:
   `SELECT * FROM v_order_summary ORDER BY order_id DESC LIMIT 1;` — новый заказ.
3. Положить в корзину 50 штук «Холодильник Bosch» и оформить. Журнал покажет
   ошибку `products_stock_check` и `ROLLBACK`; в DBeaver число заказов не изменилось.
4. Открыть «Стиральная машина LG» (нет в наличии) → «Купить в 1 клик» —
   исключение из `place_order`.
5. Управление → удалить заказ → каскад; удалить товар с продажами → RESTRICT.

После показа вернуть базу в исходное состояние:

```bash
docker compose down -v && docker compose up -d
```

## Файлы

- `src/App.java` — HTTP-сервер и все запросы к базе
- `src/Sql.java` — подключение, транзакции и журнал команд
- `src/Ddl.java` — view и функция из `07_views_procedures.sql`
- `src/Json.java` — чтение и запись JSON
- `public/index.html` — интерфейс магазина
- `run.sh` — компиляция и запуск
